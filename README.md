# Сервис поиска достопримечательностей

## Назначение
Небольшое приложение, которое помогает найти достопримечательности в городе —
например, по категории (музей, парк и т.д.) — и посмотреть базовую информацию
о них: часы работы, цену билета, статус (открыто/закрыто прямо сейчас).

## Целевая аудитория
Туристы и просто жители города, которые хотят посмотреть, куда можно сходить,
не листая кучу разных сайтов.

## Предметная область
Достопримечательности города: музеи, парки, памятники и подобные места, куда
можно сходить в свободное время.

В ПР2 достопримечательность представлялась словарём, а работа с коллекцией
достопримечательностей выполнялась отдельными функциями (`add_attraction()`,
`find_attraction()`, `filter_by_category()`, `sort_attractions_by_price()`,
`calculate_price()`). В ПР3 достопримечательность стала объектом класса
`Attraction`: данные (`id`, `name`, `category`, `open_hour`, `close_hour`,
`price`) и связанное с ними поведение (проверка, открыта ли она сейчас;
строковое представление) объединены в одном объекте.

## Основные сущности

### Attraction — достопримечательность
Объект `Attraction` представляет одну достопримечательность города.

Основные атрибуты:
- `id` — уникальный идентификатор;
- `name` — название;
- `category` — категория (музей, парк и т.д.);
- `open_hour` — час открытия;
- `close_hour` — час закрытия;
- `price` — базовая цена билета.

Основные методы:
- `is_open_now()` — проверка, открыта ли достопримечательность в текущий час;
- `calculate_price(base_price, has_discount, discount_percent=20)` —
  статический метод расчёта цены со скидкой (не привязан к конкретному
  объекту, так как пользователь может ввести произвольную базовую цену);
- `from_data(data)` — метод класса, создающий объект `Attraction` из словаря
  данных (используется при загрузке из JSON);
- `to_dict()` — преобразование объекта обратно в словарь (для сохранения
  в JSON);
- `__str__()` — строковое представление достопримечательности, включающее
  статус "открыто"/"закрыто".

## Основные операции
- показать список всех достопримечательностей;
- поиск достопримечательности по названию;
- фильтрация по категории;
- сортировка по цене;
- расчёт цены билета с учётом скидки;
- добавление новой достопримечательности (с сохранением в файл).

Функции модуля `attractions.py` (`add_attraction()`, `find_attraction()`,
`filter_by_category()`, `sort_attractions_by_price()`) работают с коллекцией
`List[Attraction]` и обращаются к данным достопримечательности через её
атрибуты (`item.name`, `item.category`, `item.price`), а не через ключи
словаря. Функция общего назначения `input_int()` (в `utils.py`) не привязана
к объекту и осталась обычной функцией.

## Хранение данных
Данные приложения хранятся в файле `data/attractions.json`. При загрузке
JSON преобразуется в объекты `Attraction` (метод `from_data()`), при
сохранении объекты преобразуются обратно в словари (метод `to_dict()`).
Формат самого JSON-файла не изменился по сравнению с ПР2.

## Назначение модулей

### `main.py`
Точка входа в приложение. Отвечает за:
- запуск приложения и отображение меню;
- получение данных от пользователя;
- организацию пользовательских сценариев.

Работает с коллекцией `List[Attraction]` и не формирует строковое
представление вручную — использует `print(item)`, который задействует
`Attraction.__str__()`.

### `attractions.py`
Содержит класс `Attraction` и функции работы с коллекцией
достопримечательностей (`add_attraction()`, `find_attraction()`,
`filter_by_category()`, `sort_attractions_by_price()`).

### `storage.py`
Отвечает за загрузку и сохранение данных. Выполняет преобразование:
- JSON → объекты `Attraction` (через `Attraction.from_data()`);
- объекты `Attraction` → JSON (через `Attraction.to_dict()`).

### `utils.py`
Содержит вспомогательную функцию `input_int()` — безопасный ввод целого
числа. Функция общего назначения, не относится к конкретному объекту.

### `tests/`
Содержит автоматизированные тесты проекта: создание объекта `Attraction`,
проверку атрибутов, `__str__()`, `is_open_now()`, `from_data()`/`to_dict()`,
а также функции работы с коллекцией и расчёт цены со скидкой.

## Git
Перед началом преобразования проекта в объектную модель была создана
контрольная точка в Git (`PR3: подготовка проекта к переходу на ООП`).
Результат ПР3 фиксируется отдельными коммитами с меткой `PR3:` в начале
сообщения, например:

```text
PR3: adapt attractions.py collection functions
PR3: adapt storage.py to object model
PR3: update tests for Attraction
PR3: update README
```
