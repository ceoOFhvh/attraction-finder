# Город рядом — сервис поиска достопримечательностей

## ПР7 — основы баз данных и SQL

Веб-часть переведена с JSON на SQLite через стандартный модуль Python
`sqlite3`. Django ORM, миграции и административная панель не используются.
Исходный JSON, класс Attraction и консольное меню ПР3 сохранены.
Шаблоны, оформление и обработка отсутствующей достопримечательности из ПР6
продолжают работать. Историческое описание — `docs/README_PR6.md`.

## Запуск

Из корня проекта (там, где manage.py):

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py runserver
```

База `data/attractions.sqlite` уже создана и входит в комплект.
Если виртуального окружения ещё нет, сначала выполните `py -m venv .venv`.
Требуется Python 3.10+. Откройте http://127.0.0.1:8000/.

## Создание базы и импорт

```powershell
.\.venv\Scripts\python.exe -m db.import_json
```

Команда применяет `sql/schema.sql`, переносит четыре исходные записи,
создаёт две категории и сохраняет исходные идентификаторы мест.
Используются `executemany`, параметры `?`, `commit`, а при ошибке — `rollback`.
Сначала создаются категории, затем места с внешним ключом `category_id`.

Повторный импорт обновляет места по ID, не создаёт дубликаты и не удаляет
записи, которых нет в JSON. Изменения совпадающих ID в SQLite будут заменены
данными JSON. Веб-сайт больше не перечитывает JSON автоматически.
Консоль `python main.py` по-прежнему работает с JSON; после добавления мест
через консоль для обновления сайта нужно повторить импорт.

Можно создать отдельную учебную базу без изменения основной:

```powershell
.\.venv\Scripts\python.exe -m db.import_json --database data/demo.sqlite
```

Исходный JSON не изменяется. Импорт проверяет типы, уникальность ID,
неотрицательную конечную цену и дневной интервал часов работы.

## Структура хранения

Таблица `categories`:

| Поле | Тип | Назначение |
| --- | --- | --- |
| id | INTEGER PRIMARY KEY | Первичный ключ категории |
| name | TEXT NOT NULL | Название для отображения |
| name_key | TEXT NOT NULL UNIQUE | Нормализованное имя для поиска без учёта регистра |

Таблица `attractions`:

| Поле | Тип | Назначение |
| --- | --- | --- |
| id | INTEGER PRIMARY KEY | Сохранённый ID из JSON |
| name | TEXT NOT NULL | Название места |
| search_name | TEXT NOT NULL | Название после Python casefold для поиска на русском |
| category_id | INTEGER NOT NULL, FK | Ссылка на categories.id |
| open_hour | INTEGER NOT NULL | Час открытия, 0–23 |
| close_hour | INTEGER NOT NULL | Час закрытия, 1–24; позже открытия |
| price | REAL NOT NULL DEFAULT 0 | Цена билета, не меньше нуля |
| description | TEXT, допускает NULL | Необязательное описание |

Связь: одна категория — много достопримечательностей.
`PRAGMA foreign_keys = ON` включается при каждом соединении.
Удаление используемой категории запрещено. Индексы созданы по категории и цене.
`description` у исходных четырёх мест равен NULL: описания не выдумывались.
При ручном переименовании обновляйте вместе `name` и `search_name`
(для категории — `name` и `name_key`); импорт делает это автоматически.
Название категории в адресе не должно содержать `/`.

## Страницы и сценарии

| Сценарий | Адрес |
| --- | --- |
| Главная с общей численностью и первыми тремя местами | `/` |
| Список, сортировка по названию или цене | `/attractions/`, `?sort=price` |
| Карточка с названием связанной категории | `/attractions/1/` |
| Категории и количество мест | `/categories/` |
| Места выбранной категории | `/categories/музей/` |
| Поиск по названию, категории, бюджету и часу | `/attractions/search/` |
| Бесплатные места | `/attractions/free/` |
| Статистика и отбор категорий по численности | `/attractions/statistics/` |

Поиск доступных помещений по дате из Roomly адаптирован к нашей теме:
поиск достопримечательностей, открытых в выбранный час, с ограничением бюджета.
В исходной модели нет бронирований и календаря; расписание считается одинаковым
каждый день. Ночные интервалы и праздничные дни не моделируются.
Статус «сейчас» вычисляется по локальному часу сервера, как в ПР3.
Поиск на 12 часов не меняет статус «сейчас» на карточке — это разные условия.

## SQL-запросы и их использование

Запросы имеют маркеры `-- name:`. Python загружает их из файла, а не дублирует
SQL в представлениях. Параметры пользователя передаются отдельно через `?`.
`db/check_queries.py` содержит фиксированные примеры аргументов каждого запроса.

| № | Имя запроса | Вид | Где используется |
| --- | --- | --- | --- |
| 1 | catalog_name | SELECT, JOIN, ORDER BY | Каталог по названию |
| 2 | catalog_price | SELECT, JOIN, ORDER BY | Каталог по цене |
| 3 | category_list | SELECT, ORDER BY | Главная и список выбора в поиске |
| 4 | detail | JOIN, WHERE | Карточка места |
| 5 | free_places | WHERE | Бесплатные места |
| 6 | search | WHERE, несколько условий | Поиск |
| 7 | category_detail | WHERE | Поиск категории по имени |
| 8 | category_places | JOIN, WHERE | Места категории |
| 9 | overview | COUNT, MIN, MAX, AVG, SUM | Главная и статистика |
| 10 | free_count | COUNT, WHERE | Статистика бесплатных мест |
| 11 | category_stats | LEFT JOIN, GROUP BY | Категории и статистика |
| 12 | price_groups | GROUP BY, CASE, AVG | Статистика платных и бесплатных мест |
| 13 | popular_categories | GROUP BY, HAVING | Фильтр на странице статистики |
| 14 | home_preview | JOIN, ORDER BY, LIMIT, OFFSET | Главная |

Таким образом, есть минимум два запроса каждого требуемого вида.
LEFT JOIN сохраняет категории без мест; COUNT(a.id) для них равен нулю.
COUNT(description) не учитывает NULL, тогда как COUNT(*) считает все строки.
Для пустой таблицы AVG/MIN/MAX возвращают NULL; шаблон показывает прочерк.

## Путь данных

URL → view → именованный SQL → sqlite3 → sqlite3.Row → контекст → шаблон.
Во view поля доступны как `row["name"]`, в шаблоне — `attraction.name`.
В ПР7 `is_open_now` в веб-карточке — вычисленный SQL-столбец, а не метод объекта.
Класс Attraction остаётся в консольной версии.
Отсутствующее место отображается веткой шаблона с HTTP 404 даже при DEBUG=True.
Некорректные параметры форм показывают сообщение с HTTP 400.
При отсутствии базы соединение не создаёт молча пустой файл: выполните импорт.

## Проверки

```powershell
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe -m pytest -v
.\.venv\Scripts\python.exe -m flake8 .
.\.venv\Scripts\python.exe -m db.check_queries
```

В Python 3.12+ можно дополнительно проверить каждый запрос во встроенном CLI:
`python -m db.check_queries --cli`. В Python 3.11 используйте вариант без
`--cli` или отдельную программу sqlite3. Пример для неё:

```text
sqlite3 data/attractions.sqlite
.headers on
.mode column
SELECT COUNT(*) FROM attractions;
SELECT c.name, COUNT(a.id) FROM categories c LEFT JOIN attractions a
ON a.category_id = c.id GROUP BY c.id, c.name;
.quit
```

62 теста проверяют старую предметную логику, консоль, страницы, импорт,
повторный импорт, откат при ошибке, ограничения, FK, фильтры, SQL-инъекции,
NULL, GROUP BY/HAVING и независимость сайта от JSON.
Тесты используют отдельные временные базы. Рабочие данные не очищаются.
Служебная папка `.pytest_tmp` удаляется pytest при новом запуске;
не храните там собственные файлы.
