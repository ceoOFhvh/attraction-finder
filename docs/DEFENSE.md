# Демонстрация ПР6 за 5 минут

1. Запустите сервер по README. Откройте главную, «Места», карточку музея,
   «Категории», категорию «Музей». Покажите сортировку и фильтр открытых мест.
2. Откройте `templates/base.html`: общая разметка и блоки `title`, `content`.
   Затем `web/catalog/templates/catalog/list.html`: `extends` заменяет блоки.
3. Покажите `web/catalog/views.py`: JSON превращается в объекты, контекст
   `attractions` передаётся в `render()`, HTML в Python отсутствует.
4. В шаблоне списка покажите `for`, `empty`, `include`. В карточке —
   `default`, `floatformat`, `truncatechars`. В статусе — `if` и вызов
   метода `is_open_now` без скобок.
5. В `web/catalog/urls.py` покажите `app_name`, `name`, `<int:attraction_id>`.
   В карточке — `{% url 'catalog:detail' attraction.id %}`.
6. В `base.html` покажите `load static`, пути к CSS и JS. Нажмите кнопку
   «Только открытые сейчас» на странице мест. Изображения лежат в `static/img`.
7. Откройте `/attractions/999/`: статус 404. Покажите результаты проверок
   в `VERIFICATION.txt`, затем выполните `git log -1 --oneline`.

## Короткие ответы

- **Контекст** — словарь, который связывает имена в шаблоне с данными Python.
- **render** — находит шаблон, подставляет контекст и возвращает HTTP-ответ.
- **extends / block** — наследование общего каркаса и замена его частей.
- **include** — подключение небольшого повторяемого фрагмента.
- **for / empty** — вывод коллекции и сообщение при её отсутствии.
- **if** — условное отображение, например статуса или бесплатного билета.
- **Фильтр** — меняет отображение значения, не исходные данные.
- **default** — подставляет запасной текст для ложного/пустого значения.
- **Namespace** — отделяет маршруты приложений с одинаковыми именами.
- **int-конвертер** — пропускает только целочисленный параметр URL.
- **404 маршрута** — URL не сопоставлен; **404 объекта** — view запущена,
  но объекта с указанным идентификатором нет.
- **TemplateDoesNotExist** — шаблон не найден; **TemplateSyntaxError** —
  шаблон найден, но его теги записаны неверно.
- **Экранирование** — `<script>` из данных выводится как текст;
  применение `safe` к пользовательским данным может привести к XSS.
- **Статика** — CSS, JS и изображения. При проблемах проверьте Network
  в браузере, путь в `static` и `python manage.py findstatic css/style.css`.
- **Почему JSON?** Сохраняется слой хранения ПР3, ORM — следующий этап.
- **Почему категории вместо бронирований?** В моём варианте сущность —
  достопримечательность. Категории уже есть в её данных и группируют места.
- **Что сохранено?** Консольное меню, класс Attraction, его методы,
  операции с коллекциями, JSON и исходные тестовые сценарии.

Для демонстрации пустого списка используйте тест `test_empty_lists`:
он меняет временный файл, а не ваши реальные данные.
Для статусов и экранирования — `test_open_status` и
`test_data_reloaded_and_escaped`. Подробности архитектуры — в README.
